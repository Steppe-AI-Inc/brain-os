# Acceptance matrix — Factory Node Management + Zero-Touch Auto Enrollment (V1)

- **Part of** the canonical contract (`docs/architecture/features/factory-node-management-auto-enrollment.md` §10). Single writer: the
  DIRECTOR capability.

## When each row runs

**On every frozen candidate SHA**, whichever WO ids the candidate claims, run by a distinct authorized verifier
(`VERIFICATION_SPEC.md`):
- **Candidate rows:** AC-5..AC-12, AC-14, AC-15, AC-16.
- **Rehearsals of the final rows:**
  - **R-1:** AC-1 in a fresh disposable Windows VM with a standard (non-admin) local account, which survives logoff and reboot. It is
    isolated from any live checkout, task or credential, never the acceptance machine, and runs against a disposable plane and local
    function runtimes.
  - **R-2:** AC-2 against the disposable plane.
  - **R-3:** AC-3 on the disposable plane with at least three enrolled test identities that report distinct machine fingerprints (for
    example three disposable VMs), with the campaign applied; or, on one machine, under the tenant default only, with the campaign's
    record-and-fingerprint rule proved by AC-14(i), (m) and (p).
  - **R-4:** AC-4 on the disposable plane, with forced interleavings.

A WO is CERTIFIED only when every row it covers has verifier evidence at that SHA. For a final row, rehearsal evidence counts. For the
live-plane parts of AC-10 and AC-11, a Director observation record counts: it is Director-committed, and the receipt cites it by sha256.
AC-10's Edge clause is PENDING in every receipt; the CERTIFIED entry cites the Edge record and the candidate's Edge reading instead.
P-8 at a candidate SHA is evidenced by AC-11 (the manifest unchanged on the copy; no new stamp) and WO-10's release-provenance inputs;
AC-13 is its final Director record.

**At final acceptance:** AC-1..AC-4, AC-5(f) repeated on the acceptance machine, then AC-13. AC-13 is the Director's acceptance record:
it is covered by no WO, and WO-10 supplies its evidence inputs. The clean acceptance machine is touched for the first time there.

**Criteria source.** Criteria are read from the Director branch at the Director commit designated for the candidate, never from the
candidate tree.

**Evidence rule** (candidate-repo ledger 218):
- A row is judged only from records that would be **different if the claim were false**: server rows; HTTP status and body, with a
  server read-back; process exit; file hashes; signed-commit verification.
- A row is never judged from an instrument's summary line or an implementer report.
- Every row records: command, principal / persona, input, expected, actual, timestamp, environment, and the candidate or release SHA.
